# 租户、版本与能力边界

生产使用不需要 OceanBase 源码，也不需要 ob_admin。基础依赖为 SQL 客户端和已有运维权限；可选脚本依赖 Python 3.10+ 标准库，采集器调用 mysql 客户端。

| 环境 | 支持方式 | 验证状态 |
|---|---|---|
| 4.x / 5.x MySQL 模式 | 运行时探测，匹配字段后生成 SQL | 离线流程与异常测试，尚无真实集群回归 |
| Oracle 模式 | 运维通过现有 Oracle 兼容客户端人工探测 | 未提供自动采集或保证可执行的 SQL 模板 |
| 无 SQL 权限 | 应用错误、已有监控和节点日志 | 只能形成有限证据判断 |

对于 Oracle 模式，通过客户端 DESCRIBE 检查目标 SYS 视图，或查询当前账号可见的数据字典获得列名；不得机械替换 oceanbase 为 SYS 后执行 MySQL 的 SHOW/LIMIT。先确认该版本官方文档和现场字典。此包的自动 SQL 生成明确只接受 MySQL 快照。

业务租户通常只看到自身数据；部分 DBA 视图使用当前有效租户过滤，即使 sys 登录也不能等同“所有业务租户”。系统级资源视图可能要求 sys 权限。对空结果必须同时核实租户、权限、保留时间及对象是否在该节点。

每次交接保留版本、模式、账号可见范围、采样时间及错误类别。视图存在仅说明名称可解析，字段存在也不能证明跨版本含义相同。未知列/权限错误时回到探测，不删掉租户过滤来使查询成功。内部虚拟表仅作为版本已确认、权限已授权的高级补充，公共诊断流程优先使用暴露的系统视图。

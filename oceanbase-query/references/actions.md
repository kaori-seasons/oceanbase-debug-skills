# 慢 SQL 与执行计划：处置边界

## 排队

确认：QUEUE_TIME 同期升高，多个 SQL_ID 受影响。

动作方向：关联租户队列和主机 CPU；优先控制请求并发。

验证：复采原对象，确认对应异常持续下降且业务恢复；如果只改善一个指标而错误率仍高，继续检查 [tenant-resource](../../oceanbase-tenant-resource/SKILL.md)。

## 计划退化

确认：相同 SQL_ID 的计划变化与延迟回归同时出现。

动作方向：比较绑定值、统计信息与执行计划；在测试环境验证候选计划。

验证：复采原对象，确认对应异常持续下降且业务恢复；如果只改善一个指标而错误率仍高，继续检查 [query](../../oceanbase-query/SKILL.md)。

## 执行等待

确认：执行耗时和 IO 或锁等待同时上升。

动作方向：先区分锁、IO 与算子耗时，保留同一次执行的 trace。

验证：复采原对象，确认对应异常持续下降且业务恢复；如果只改善一个指标而错误率仍高，继续检查 [transaction](../../oceanbase-transaction/SKILL.md)。

L0 为有界只读查询与日志检查；L1 为有副作用的会话诊断；L2 包括改参数、终止会话、重启及侵入式采样；L3 包括强制副本/事务操作、故障注入和直接删除存储文件。debug_sync 不作为常规生产诊断。

任何变更必须记录原状态、目标范围、停止条件和恢复方案。终止事务与重启没有等价逆操作，不能把“重连”写成回滚；应说明重试、事务一致性及业务补偿。不得为了临时恢复随意关闭写限流或扩大内存上限。

# 事务、行锁与死锁

先读[租户与版本前提](../references/03-tenant-and-version.md)。生产环境无需源码；使用数据库实际返回的视图与列。当前包尚未完成真实集群回归，不得声称所有版本都支持示例。

## Phase 1 — 确认范围

记录事故时间与时区、连接入口、租户、模式、节点、业务症状与最近变更。先获取[运行时能力快照](../references/01-common-commands.md)，再读本技能的[查询与判读](references/queries.md)。区分无权限、不存在、连接失败和查询结果为空。错误码需要注明 OB 内部码还是客户端映射码。

## Metric Taxonomy

| 层次 | 观测 | 判读限制 |
|---|---|---|
| 业务 | 错误率、吞吐、p95/p99 | 与同负载基线比较 |
| 数据库 | `GV$OB_LOCKS` | 先探测字段，按租户/节点/时间限定 |
| 关联面 | `GV$OB_TRANSACTION_PARTICIPANTS` | 只能证明可见范围内的状态 |
| OS/日志 | 同时段 CPU、IO、进程与日志 | 对齐节点和时区，相关性不等于因果 |

## Phase 2 — 缩小根因

| 候选原因 | 确认条件 | 下一步与交接 |
|---|---|---|
| 锁等待链 | 等待者和 holder 标识可连接，连续采样阻塞仍存在 | 沿 ID1/ID2 追踪持锁事务；确认事务所有者、业务语义和回滚成本；[transaction](../oceanbase-transaction/SKILL.md) |
| 死锁 | 死锁历史记录给出同一事件的闭环 | 用事件时间和参与者还原顺序；统一应用加锁顺序；[transaction](../oceanbase-transaction/SKILL.md) |
| 分布式提交停滞 | 同一事务多个参与者多次采样未推进且日志异常 | 携事务/LS/节点时间线转日志诊断；未决事务不能任意强制终结；[election-ha](../oceanbase-election-ha/SKILL.md) |

对同一对象取至少两次带时间戳的样本，确认趋势；选择一个最能区分当前假设的观测，不循环扫描全库。SQL_AUDIT 是有限保留的数据，事故记录缺失不能当作没有异常。

## Phase 3 — 按证据处置

- **锁等待链**：只有在“等待者和 holder 标识可连接，连续采样阻塞仍存在”成立时推进。沿 ID1/ID2 追踪持锁事务；确认事务所有者、业务语义和回滚成本。同时记录能推翻该判断的反例，验证失败则回到 Phase 2。
- **死锁**：只有在“死锁历史记录给出同一事件的闭环”成立时推进。用事件时间和参与者还原顺序；统一应用加锁顺序。同时记录能推翻该判断的反例，验证失败则回到 Phase 2。
- **分布式提交停滞**：只有在“同一事务多个参与者多次采样未推进且日志异常”成立时推进。携事务/LS/节点时间线转日志诊断；未决事务不能任意强制终结。同时记录能推翻该判断的反例，验证失败则回到 Phase 2。

涉及参数、会话终止、重启或副本动作时，执行前写明对象、影响、原值、回退和观察窗口，并确认已有授权涵盖该动作。不得从诊断授权推导变更授权。L3 操作只说明风险与升级路径，不生成可复制命令。详见[处置边界](references/actions.md)。

## Phase 4 — 验证恢复

在可比负载下检查业务错误率、吞吐和延迟，并复采同一租户/节点/对象的异常指标。建议覆盖多个采样周期和至少一个业务事务周期；只恢复进程或告警消失不足以关闭事件。输出：证据、支持/排除的假设、已执行动作、未执行建议、恢复状态、仍缺信息。

## 因果链

- 锁等待链 → 等待者和 holder 标识可连接，连续采样阻塞仍存在 → 业务退化；断点：沿 ID1/ID2 追踪持锁事务；确认事务所有者、业务语义和回滚成本。用前后同范围样本验证，不能将链条当成已确认事实。
- 死锁 → 死锁历史记录给出同一事件的闭环 → 业务退化；断点：用事件时间和参与者还原顺序；统一应用加锁顺序。用前后同范围样本验证，不能将链条当成已确认事实。
- 分布式提交停滞 → 同一事务多个参与者多次采样未推进且日志异常 → 业务退化；断点：携事务/LS/节点时间线转日志诊断；未决事务不能任意强制终结。用前后同范围样本验证，不能将链条当成已确认事实。
